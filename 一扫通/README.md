# 一扫通

> 扫一次码，自动跳到对应的 App。

线下扫码最烦的是「这个码该用哪个 App 扫」——微信码要用微信，支付宝码要用支付宝，QQ 码要用 QQ，扫错了就是白扫一次。

**一扫通** 把这步省掉：扫一次，自动跳到正确的 App。

## 功能

- **4600+ 条跳转规则**，覆盖收款支付、登录验证、停车缴费、充电、点餐、购物电商、政务医疗等 14 个分类
- **支付宝收款码直达收银台** —— 不是打开 App 再扫一次，而是把码的内容直接送进付款页
- **微信收款码 / 微信号** 微信未对外开放协议，自动交回微信扫一扫，并说明为什么不能直连
- **聚合收款码**（一张码微信、支付宝、云闪付都能付的那种）可在设置里指定优先唤起哪个 App
- **规则库没收录的 App** 也补齐了：网易云音乐、QQ音乐、知乎、微博、饿了么、快手、58同城…
- **内容解析**：扫到什么、能不能直跳，一眼看清；原始内容可一键复制
- **从相册识别** 二维码，不用非得对着实物扫

## 小组件

| 位置 | 尺寸 | 行为 |
| :--- | :--- | :--- |
| 桌面 | `systemSmall` | 点一下直接进相机扫码 |
| 锁屏 | `accessoryCircular` / `accessoryRectangular` | 显示上次记录，点一下进相机 |

从小组件点进来时**总是**直接扫码；在 Scripting 里手动运行则只看界面（可在设置里改）。

## 设置

| 项 | 说明 |
| :--- | :--- |
| 打开脚本即扫码 | 只影响在 Scripting 里手动运行的情况 |
| 扫到后自动跳转 | 命中后 0.5 秒自动唤起，也可以先看候选再手动点 |
| 无匹配时优先 | 微信 / 支付宝 |
| 聚合收款码优先 | 自动 / 微信 / 支付宝 / 云闪付 |
| 保留跳转记录 | 最多 30 条，超出自动淘汰最旧的 |

```

└── pages/
    ├── HomePage.tsx     扫码、识别结果、候选跳转、最近记录

    └── SettingsPage.tsx 设置
```

## 匹配引擎

优先级从高到低：

1. **内容本身就是 scheme**（如 `weixin://wxpay/...`）→ 直接打开
2. **内置核心规则**（50000 分）—— 收款码、微信号、公众号文章、银联等
3. **域名 → App 表**（40000 分）—— 补齐规则库没收录的 App
4. **聚合收款码**（30000 分）—— 按设置优先唤起
5. **规则库**（最高约 1500 分）—— 4592 条
6. **回退** —— 网址开浏览器，其它交给默认 App 扫一扫

> 得分设计的关键：核心规则（50000）永远高于聚合收款码设置（30000），
> 所以 `qr.alipay.com`、`wxp://` 这类专属码不会被「聚合码优先」劫持。

## 关于规则数据

`rules.ts` 里的 4592 条规则来自 [sumqt.com](https://sumqt.com) 的「一扫 自定义方案中心」，
抓取全量 4613 条后去重、规范化生成。规则语义经过逆向：

- **type 1** = 只匹配链接（`|` 分隔的多段，含正则元字符的段按正则处理）
- **type 2** = 链接 **且** 正则都要命中

生成过程中还修了规则库自身的一些问题，例如 QQ 扫一扫的 scheme 少了 `&src_type=app`
（会导致只打开 QQ 主界面而不进扫一扫）。

## 隐私

扫码记录只写入本机 Scripting 的「脚本私有存储」（`Storage`），全程不联网、不上传任何服务器。
代码里没有任何网络请求，跳转规则也是内置在脚本里的。

## 安装

1. 安装 [Scripting App](https://apps.apple.com/app/apple-store/id6479691128)
2. 从本仓库下载 `一扫通/` 目录，放进 Scripting 的 `scripts/` 目录
3. 回到 Scripting 运行「一扫通」

> 需要一键导入的 `.scripting` 安装包，请在 Scripting 里打开项目 → 导出，生成后放入本目录即可。
